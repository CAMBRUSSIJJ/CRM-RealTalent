Regressão histórica profunda
----------------------------
`npm run check:legacy` foi executado integralmente após migrar os meta-gates antigos
para `check:legacy`. Resultado: 3.939 checks OK / 0 FAIL.

Mudança do pipeline
-------------------
ANTES:
  npm run check -> mais de uma centena de audits históricos por versão -> typecheck -> Vitest -> build

AGORA:
  npm run check
    -> qa:architecture
       -> syntax
       -> integration contracts
       -> migrations
       -> release manifest
       -> capability matrix
       -> repository parity
       -> critical browser-flow contract
       -> V101.9.9 architecture audit
    -> typecheck
    -> Vitest
    -> build

A regressão antiga permanece disponível em `npm run check:legacy`, mas deixa de ser
o gate padrão de cada release.

Browser E2E
-----------
O catálogo possui 7 fluxos críticos: Meu Dia, Contatos, Pipeline, Comunicação,
Ligações/Connect, Automações e Configurações. O contrato estrutural 7/7 foi executado.
Também foi incluído `npm run e2e:browser:critical`, que usa Chromium/Chrome contra o
`dist/` depois do build quando esse navegador estiver disponível. O browser real não
foi executado nesta montagem porque não houve `node_modules`/build.

Limitação do ambiente de montagem
---------------------------------
`npm install --no-audit --no-fund` foi tentado com timeout controlado e expirou por
rede, sem criar `node_modules`. Por isso `npm run check` avançou por toda a nova
arquitetura de QA e parou no typecheck global por módulos ausentes (React, Lucide e
Supabase). Vitest/build também não puderam ser executados aqui.

O `start-linux.sh` preserva o gate completo no Linux:
  npm install -> preflight -> qa:architecture -> typecheck -> Vitest -> build -> runtime smokes.

Critério da V101.9.9
--------------------
A unidade principal de confiança deixa de ser a presença de strings de versões antigas
em `npm run check` e passa a ser a capacidade comprovada por teste, smoke, contrato,
repository parity, integração, migration invariant ou browser flow.
