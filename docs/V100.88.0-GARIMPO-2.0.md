# Garimpo 2.0 — operação

O fluxo passa a ser: **Capturar/Importar → Analisar → Revisar pelo Data Layer → Aprovar → Enviar ao CRM**.

## Data Layer
O Data Layer não aprova pelo percentual de confiança. Ele calcula quatro dimensões auxiliares (Identidade, Contato, Origem e Cobertura), mas a prontidão é determinada por critérios operacionais:

- bloqueado: identidade ausente, nenhum canal de contato ou duplicidade confirmada;
- revisão necessária: ainda precisa análise/complementação;
- pronto para aprovação: identidade e contato utilizáveis, sem bloqueio e com análise executada.

## Enriquecimento externo
O botão **Data Layer** exporta um JSON com contrato `realtalent-data-layer/2.5`. A ferramenta externa pode enriquecer `records[].data` e devolver o mesmo contrato. Ao importar o retorno, o Garimpo atualiza o registro existente por identidade forte.

## Segurança operacional
Registros não aprovados ou bloqueados não entram no modal de envio ao CRM. Duplicidades continuam permitindo decisão humana via política de atualização/ignorar/criar quando o registro já foi aprovado e está apto para o lote.
