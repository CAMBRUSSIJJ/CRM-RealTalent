# V100.90.0 — RealTalent AI

## Arquitetura

`Assistant UI → RealTalent AI Gateway → Context Engine + Commercial Memory + Tool Policy → Provider`

O provider não recebe autoridade de persistência. A execução de ações fica no aplicativo, sujeita às permissões do usuário, validação do estado atual e confirmação explícita.

## Context Engine

O envelope `realtalent-ai-context/1.0` contém identificação do workspace, rota/foco, memória comercial derivada, catálogo de tools e contagens operacionais. Ele declara explicitamente `sendsExternally=false`, `includesSecrets=false` e `writeAuthority=false` no provider local.

## Memória comercial

A memória não é um banco paralelo. Ela é reconstruída a partir dos registros atuais do CRM para reduzir risco de fatos obsoletos: etapa, notas, stakeholders, atividades, ligações, reuniões e proposta corrente.

## Tools

Ferramentas são declaradas individualmente. Tools de leitura/rascunho não modificam dados. Tools de escrita exigem `requiresConfirmation=true`. Capacidades como envio automático e mudança direta do Pipeline permanecem reservadas.

## Auditoria

A trilha local guarda metadados técnicos da execução, mas não o texto integral da pergunta. Isso permite diagnóstico sem criar um histórico oculto de conversas.

## Próximo passo

Um provider generativo poderá ser conectado ao Gateway sem alterar a política de tools. Antes disso, deve existir backend server-side para credenciais, minimização/redação de contexto, política de retenção e conjunto de avaliações para medir factualidade e qualidade comercial.
