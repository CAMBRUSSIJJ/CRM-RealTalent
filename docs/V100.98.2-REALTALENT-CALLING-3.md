# V100.98.2 — RealTalent Calling 3.0

## Arquitetura

```text
CRM :4183
  |
  | RealTalent Voice API v1
  v
RealTalent Connect :3001
  |
  | adapter de provider
  v
Twilio Agent Bridge
  |
  +--> telefone do vendedor (perna A)
          |
          +--> telefone do lead (perna B)
```

O browser não recebe credenciais da operadora. O Connect recebe apenas chamadas de origens locais autorizadas do CRM e escuta em `127.0.0.1` por padrão.

## Endpoints
- `GET /api/voice/v1/health`
- `GET /api/voice/v1/capabilities`
- `POST /api/voice/v1/calls`
- `GET /api/voice/v1/calls/:id`
- `POST /api/voice/v1/calls/:id/commands`

Na V100.98.2 o comando remoto implementado pelo Twilio Agent Bridge é `hangup`. Recursos não implementados retornam erro explícito e não aparecem no catálogo de capabilities.

## Estado real da chamada
A chamada pai representa a perna do vendedor. Depois que o vendedor atende, o Connect consulta as chamadas filhas (`ParentCallSid`) para acompanhar a perna do lead. Assim:

- agente tocando → `ringing`;
- agente atendeu, lead ainda sendo conectado → `connecting`;
- lead tocando → `ringing`;
- lead atendeu → `connected`;
- encerrada → `ended`;
- busy/failed/no-answer → `failed`.

O frontend consulta esse estado e publica `realtalent:voice-event` somente quando ele muda.

## Configuração

```bash
./configure-realtalent-connect.sh
```

São solicitados:
- Twilio Account SID;
- Twilio Auth Token;
- número Twilio de origem em E.164;
- telefone do vendedor/agente em E.164;
- código de país padrão para leads sem prefixo internacional.

O `.env.local` recebe permissão `600` quando possível. O token é transferido ao helper por variável de ambiente do processo, não por argumento de linha de comando.

## Fluxo de sessão
### Preparar
A sessão resolve fila, objetivo, Playbook e telefonia. O `playbookId` efetivo entra no `CallSessionConfig`.

### Conectar
O vendedor inicia a ação explicitamente. Não existe autodiscagem escondida. Se o provider for o RealTalent Connect, o telefone do vendedor toca primeiro.

### Conversar
A tela prioriza etapa do roteiro, fala sugerida, pergunta e coaching curto. Assistant, objeções e contexto ficam progressivamente revelados.

### Registrar
O wrap-up reúne outcome, notas e próxima ação. O registro continua usando `registerCallOutcome` e mantém o histórico comercial existente.

## Segurança operacional
- binding local `127.0.0.1`;
- allowlist de origens do CRM (`127.0.0.1`/`localhost` na porta atual);
- POST apenas com JSON;
- credenciais fora do bundle Vite;
- números normalizados para E.164;
- nenhuma chamada é simulada quando o provider está ausente;
- launcher testa o health do bridge antes de abrir o CRM.

## Preservação do Prospecting Engine
O gateway de Google Places/CNPJ continua implementado como plugin server-side do Vite. A inclusão do RealTalent Connect não remove esse runtime.
