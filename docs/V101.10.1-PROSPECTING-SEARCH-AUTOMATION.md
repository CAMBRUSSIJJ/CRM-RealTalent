# V101.10.1 — Prospecting Search Automation

## Arquitetura

```text
Garimpo
  ↓
Prospecting Search Automation
  ├─ plano de queries
  ├─ múltiplas regiões
  ├─ orçamento de requests
  ├─ paginação
  ├─ deduplicação incremental
  ├─ progresso
  └─ cancelamento
  ↓
Prospecting Provider Gateway
  ├─ Supabase Edge Function
  └─ Gateway local Vite
  ↓
Google Places API (New)
  ↓
CaptureDraft[]
  ↓
RealTalent Data Layer
  ↓
Processamento → Revisão → Resultados → Contatos
```

## Serviço principal

`src/services/prospecting-search-automation.ts`

Responsabilidades:

- normalizar regiões;
- construir consultas;
- limitar meta a 100 resultados únicos;
- limitar quantidade de requests;
- consumir `nextPageToken`;
- deduplicar durante o fetch;
- emitir progresso;
- preservar lote parcial quando cancelado entre requests.

A camada não conhece React e pode ser testada isoladamente.

## Provider Gateway

`ProspectingProviderSearchInput` ganhou `pageToken`.

Tanto o gateway local em `vite.config.ts` quanto a Edge Function `supabase/functions/prospecting-search/index.ts` encaminham o token ao Google Places Search Text e solicitam `nextPageToken` no field mask.

Cada request continua limitado a no máximo 20 resultados. A agregação maior acontece no orquestrador, não em uma chamada individual.

## Estratégia de deduplicação

A coleta mantém um índice em memória com chaves derivadas de:

1. Place ID;
2. CNPJ válido;
3. telefone normalizado;
4. domínio do website;
5. nome da empresa + cidade.

Um resultado que colide com qualquer sinal já coletado não aumenta a meta.

Depois disso, o lote ainda passa pelas regras normais do Data Layer do Garimpo.

## Estados

```text
idle
planning
searching
completed
cancelled
failed
```

A interface mostra o estado, meta, encontrados, requests e consulta atual.

## Cancelamento

O cancelamento impede novas páginas/consultas. Como o fetch atual pode já estar em trânsito, o cancelamento é observado entre chamadas; os resultados de chamadas concluídas antes da parada são preservados.

## Limites da release

Não incluído nesta versão:

- busca recorrente agendada;
- scraping automático de Instagram;
- crawler genérico de sites;
- descoberta em massa de CNPJ.

Essas funções exigem providers/contratos próprios e não devem ser simuladas por automação frágil de DOM.
