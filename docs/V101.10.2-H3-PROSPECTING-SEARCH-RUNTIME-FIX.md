# V101.10.2-H3 — Prospecting Search Runtime Fix

## Problema observado
O Agent podia estar saudável em `127.0.0.1:4319`, mas o job parava antes de descobrir empresas quando a geocodificação externa falhava. O erro também chegava ao usuário como `fetch failed`, sem indicar qual provider havia falhado.

## Pipeline H3
1. Segmento + região + meta chegam ao Agent local.
2. Tenta Nominatim para obter bounding box.
3. Consulta Overpass por bounding box.
4. Se geocodificação falhar, consulta a área administrativa diretamente pelo nome no Overpass.
5. Processa resultados OSM e deduplica contra CRM/histórico.
6. Se a meta ainda não foi atingida, usa busca web pública conservadora.
7. Visita sites públicos, respeita robots.txt e extrai telefone/e-mail/CNPJ/redes.
8. Retorna resultados ao CRM para revisão.

## Diagnóstico de falhas
O runtime diferencia DNS (`EAI_AGAIN` / `ENOTFOUND`), conexão recusada e timeout. O health expõe estado dos providers e a busca preserva warnings por região.

## Restrições
Não há bypass de CAPTCHA, login automatizado ou mecanismo para contornar bloqueios de sites.
