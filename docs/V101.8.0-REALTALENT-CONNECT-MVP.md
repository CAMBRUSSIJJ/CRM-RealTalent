# V101.8.0 — RealTalent Connect MVP

## Arquitetura
`CRM :4188 → RealTalent Connect :3001 → RealTalent Phone → discador nativo`.

O launcher inicia o Connect em `0.0.0.0:3001`, enquanto o CRM continua servido apenas em loopback. O desktop acessa a API pela origem local autorizada; o telefone usa um token obtido por pareamento temporário.

## Pareamento
O CRM solicita `/api/phone/v1/pairing?workspaceId=...`. O Connect devolve código, URL LAN e QR local. O telefone abre `/phone`, envia o código e recebe um token de device. O código é rotacionado após uso. O usuário pode gerar um novo código ou revogar o aparelho.
Enquanto a tela de configuração permanece aberta, o CRM sincroniza a presença do aparelho periodicamente para que um novo pareamento apareça sem recarregar a página.

## Tempo real
O phone abre `/api/phone/v1/ws?token=...`. O CRM monitora cada chamada em `/api/voice/v1/ws?callId=...`. Se WebSocket falhar, o CRM preserva o polling histórico para evitar perda de estado.

## Chamada assistida
O CRM envia telefone, contato, empresa, playbook, objetivo e sessionId. O celular exibe esse contexto e só abre o discador quando o usuário toca em “Abrir discador do celular”. Ao retornar, o usuário confirma `Atendeu`, `Não atendeu` ou `Finalizar`, e o estado volta ao Modo Foco.

## Segurança
- Sem CORS wildcard.
- API desktop restringida às origens locais configuradas.
- Phone usa token de alta entropia.
- Device store e runtime store usam modo 0600.
- Device pode ser revogado a qualquer momento.
- Pairing expira em 10 minutos e é vinculado ao workspace quando fornecido.
