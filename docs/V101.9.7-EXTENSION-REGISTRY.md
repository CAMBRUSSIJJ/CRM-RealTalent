# V101.9.7 — Extension Registry

## Objetivo

Transformar integrações que antes possuíam metadata espalhada em uma camada de plataforma declarativa e extensível.

## Arquitetura

```text
ExtensionManifest
  ├─ provider
  ├─ scopes
  ├─ capabilities
  ├─ jobs
  ├─ commands/actions
  ├─ featureFlags
  └─ lifecycleHooks
        ↓
ExtensionRegistry
        ├─ Integration Framework
        ├─ Permission Matrix
        ├─ RealTalent Connect
        ├─ Central de Integrações
        └─ Inspector
```

## Extensões nativas

1. `google-workspace` — Gmail + Google Calendar.
2. `microsoft-365` — Outlook + Microsoft Calendar.
3. `meta-business` — Facebook, Instagram e Lead Ads.
4. `whatsapp-cloud` — WhatsApp Business Platform oficial.
5. `realtalent-connect` — telefonia e One-Tap.
6. `realtalent-capture` — extensão de garimpo.

## Commands/actions

Commands possuem ID global, ação de permissão, recurso, capability, scopes e job opcional. Isso permite evoluir futuramente para handlers plugáveis sem acoplar cada tela a um provider específico.

## Feature flags

Cada manifest declara flags com valor padrão. Overrides em runtime podem ser aplicados sem alterar o manifest. Nesta release os defaults preservam todas as capacidades já existentes.

## Lifecycle

OAuth, sync e RealTalent Connect publicam eventos em um lifecycle comum. O histórico é somente de runtime e serve para diagnóstico/inspeção; não substitui a auditoria persistente do Integration Framework.

## Segurança

Scopes deixam de ser duplicados dentro da Permission Matrix. O engine consulta `listRegisteredIntegrationScopes()` e continua aplicando implicit deny para scopes desconhecidos conforme a política existente.

## Persistência

Nenhuma migration nova. O registro é código de plataforma; contas, jobs, tokens e auditoria continuam nas tabelas já existentes.
