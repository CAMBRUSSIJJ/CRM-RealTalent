# V101.9.9-H4 — Workspace Appearance & Theme Personalization

## Objetivo

Separar **identidade visual** de **estrutura funcional**. A H4 permite mudar a aparência do CRM sem modificar módulos, dados, permissões, views ou regras comerciais.

## Arquitetura

```text
CrmPreferences.appearance
        ↓
normalizePreferences()
        ↓
resolveAppearanceTheme()
        ↓
CSS variables no :root
        ├─ Design System
        ├─ Topbar
        ├─ Sidebar
        ├─ Canvas
        └─ Cards / Panels
```

## Personalizado

O modo Personalizado permite selecionar individualmente:

- `accentColor`;
- `topbarColor`;
- `sidebarColor`;
- `canvasColor`;
- `surfaceColor`.

As cores são normalizadas como HEX de seis dígitos antes da persistência. O editor textual só aplica um valor completo e válido; valores incompletos não chegam ao runtime do tema.

## Contraste

`contrastTextColor()` usa luminância relativa para escolher texto claro ou escuro. `resolveAppearanceTheme()` deriva ainda:

- texto/muted da topbar;
- fundo de controles da topbar;
- bordas da topbar;
- texto/muted da sidebar;
- item ativo;
- accent suave;
- texto de conteúdo;
- bordas e superfícies secundárias.

Isso evita repetir o problema de ícones e textos quase invisíveis observado antes da H4.

## Preview e persistência

A aba Aparência aplica o `draft` em tempo real por `applyPreferences()`. O salvamento continua usando o fluxo normal de Configurações. Ao sair da aba sem salvar, um efeito de cleanup reaplica as preferências persistidas.

## Retrocompatibilidade

Workspaces sem as novas propriedades recebem o preset Minimal durante a normalização. Aliases CSS antigos (`--blue`, `--accent`, `--primary`, `--navy`) continuam apontando para o accent resolvido para que módulos ainda não migrados não quebrem.
