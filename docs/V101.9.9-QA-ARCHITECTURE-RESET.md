# V101.9.9 — QA Architecture Reset

## Modelo

```text
Release Manifest
      ↓
Capability Matrix
      ├─ unit/component evidence
      ├─ repository evidence
      ├─ integration evidence
      ├─ runtime smoke
      ├─ migration invariants
      └─ browser critical flows
      ↓
qa:architecture
      ↓
typecheck → Vitest → build
```

## Gates
- `npm run qa:architecture`: gate estrutural rápido e determinístico.
- `npm run check`: gate padrão de release; usa `qa:architecture`, TypeScript, Vitest e build.
- `npm run check:legacy`: regressão histórica profunda, preservada como diagnóstico, não como gate principal.
- `npm run e2e:browser:critical`: valida as rotas críticas em Chromium quando `dist/` e Chromium estiverem disponíveis.

## Capability Matrix
Cada capacidade possui tier, owner e evidências. Capacidades críticas exigem pelo menos duas evidências e ao menos uma evidência executável.

## Repository Contract
O contrato `CrmRepository` é comparado estruturalmente com Local e Supabase. Isso evita que um backend evolua sem o outro.

## Browser flows
Meu Dia, Contatos, Pipeline, Comunicação, Ligações/Connect, Automações e Configurações são catalogados como fluxos críticos. O contrato de rotas é sempre verificado; o browser real é um gate adicional quando Chromium está disponível.
