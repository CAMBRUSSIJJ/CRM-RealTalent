# V101.10.9 — CSS & Design System Consolidation

## Objective

Reduce CSS runtime fragmentation without redesigning CRM screens or changing product behavior. This release establishes a controlled migration path from version-suffixed stylesheets to canonical, versionless domain stylesheets.

## First consolidation wave

Three domains were selected because their historical stylesheets are loaded contiguously and can be merged without changing cascade order:

- Pipeline: `pipeline-v100.css` + `pipeline-v10076.css` → `pipeline.css`
- Follow-ups: `followups-v100.css` + `followups-v10077.css` → `followups.css`
- RealTalent Connect: five historical layers → `realtalent-connect.css`

The source CSS is copied in the same historical order. No selector is renamed and no declaration is intentionally changed in this wave.

## Legacy policy

The previous CSS files are retained as audit and rollback sources, but are no longer imported by `src/main.tsx` for the migrated domains. A frozen allowlist (`qa/css-legacy-allowlist.json`) prevents new version-suffixed CSS debt from being introduced silently.

## Governance

`npm run css:inventory` regenerates the CSS inventory report.

`npm run css:governance` verifies:

- no new version-suffixed stylesheet has appeared outside the frozen baseline;
- canonical runtime imports are active;
- legacy source order is preserved inside canonical stylesheets;
- the registry-independent build excludes superseded runtime CSS;
- the Design System remains later in the cascade than Connect.

## Deliberately unchanged

- no data migration;
- no Supabase schema change;
- no IndexedDB migration;
- no React domain logic change;
- no Communications/WhatsApp/Connect protocol change;
- no visual redesign;
- no removal of historical CSS source files yet.

## Next waves

Contacts, workspace/global filters, Calls and Prospecting remain versioned and should be consolidated only after per-domain visual/runtime equivalence checks.
