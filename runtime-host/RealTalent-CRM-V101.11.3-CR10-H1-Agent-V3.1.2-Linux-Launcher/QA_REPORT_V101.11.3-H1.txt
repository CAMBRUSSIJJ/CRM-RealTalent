RealTalent CRM
V101.11.3-H1 — Communications Gateway Recovery

ESCOPO
Hotfix de runtime sobre V101.11.3 — Actionable Pipeline Experience.
Sem mudança de schema, dados, Pipeline, Teams & Tasks, Login ou UX interna do CRM.

INCIDENTE OBSERVADO NO LINUX
- Vite production build concluiu no ambiente do usuário.
- A falha ocorreu na etapa 3/4, ao aguardar o Communications Gateway.
- O log fornecido não inclui o conteúdo de .realtalent-communications.log, portanto não prova a exceção interna específica.
- A auditoria do launcher encontrou duas fragilidades capazes de produzir esse sintoma:
  1) novo supervisor era iniciado sem recuperar um gateway/supervisor RealTalent antigo na porta 3002;
  2) qrcode era importado estaticamente no boot do Gateway, permitindo que um recurso de QR impedisse o /health de subir.

CORREÇÕES
1. PRE-FLIGHT DA PORTA 3002
- prova primeiro se já existe Gateway saudável com token/versão esperados;
- Gateway saudável pode ser reutilizado.

2. RECUPERAÇÃO SEGURA DE PROCESSOS ÓRFÃOS
- Linux inventaria processos por /proc + cwd + cmdline;
- reconhece apenas realtalent-communications-supervisor.mjs e realtalent-communications-gateway.mjs;
- encerra processos da release atual;
- para releases irmãs, somente encerra a release comprovadamente dona da porta 3002;
- outro runtime RealTalent fora desse escopo permanece intacto;
- processo desconhecido na porta nunca é morto automaticamente.

3. FAIL-SOFT
- Communications Gateway indisponível não encerra mais todo o CRM;
- Pipeline, Contatos, Tarefas, Equipes, Calling e demais módulos continuam abrindo;
- Communications fica marcado como indisponível/degradado.

4. DIAGNÓSTICO NO TERMINAL
- mostra HTTP/probe final;
- mostra ocupação da porta e PID quando disponível;
- imprime as últimas 50 linhas de .realtalent-communications.log;
- adiciona boundary de startup no log para distinguir tentativas.

5. DOCTOR
- npm run doctor mostra porta, processos RealTalent e log recente;
- doctor permanece não destrutivo: não mata processos nem inicia serviços.

6. QR LAZY LOAD
- qrcode não é mais importado durante o boot do Gateway;
- só é carregado quando uma sessão QR realmente pede geração do código;
- whatsapp-web.js continua lazy-loaded.
