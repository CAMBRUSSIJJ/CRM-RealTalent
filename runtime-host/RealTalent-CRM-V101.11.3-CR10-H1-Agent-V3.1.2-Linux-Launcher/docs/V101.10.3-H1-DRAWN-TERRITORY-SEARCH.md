# V101.10.3-H1 — Drawn Territory Search

## Objetivo

Transformar `areaMode: map` em uma geometria operacional. O polígono desenhado pelo usuário é a autoridade territorial para o planejamento e para a aceitação dos resultados geolocalizados.

## Contrato de entrada

```ts
mapPolygon: Array<{ lat: number; lon: number }>
```

O Agent sanitiza coordenadas, remove fechamento duplicado e exige no mínimo 3 vértices.

## Planejamento

1. Calcula o `bbox` do polígono.
2. Gera o grid conforme `searchMode`.
3. Mantém apenas células que intersectam o polígono.
4. Calcula `areaKm2` pelo polígono, não pelo bounding box.
5. Persiste `plan.geometry` para auditoria e visualização.

## Execução

O Overpass continua sendo consultado por célula/bbox. Cada elemento retornado é convertido em candidato e, no modo mapa, só segue para o Company Resolver quando `latitude/longitude` estão dentro do polígono.

A subdivisão de célula densa também aplica `bboxIntersectsPolygon`, evitando expandir trabalho fora da área escolhida.

## Web discovery

A descoberta web ampla é desabilitada como fonte de descoberta no modo polígono. Sem coordenada verificada, não é possível garantir aderência territorial. O enrichment web dos candidatos internos continua permitido.

## UI

O seletor usa a região geocodificada pelo endpoint local `/api/prospecting-agent/territory/preview` e permite marcar os vértices diretamente sobre um mapa OSM de referência. O frontend envia os pontos ao job/campaign e impede execução com geometria incompleta.
