# V101.10.3-H5 — Independent Enrichment Jobs

## Objetivo

Transformar o enriquecimento do Garimpo em uma esteira persistente e reprocessável por empresa. Website, contatos, CNPJ e redes deixam de ser um único bloco sequencial opaco.

## Jobs

Cada `CompanyCandidate` recebe quatro tarefas:

- `website`: descobre e valida o website oficial usando busca web pública e crawler compatível com robots.txt;
- `contacts`: extrai telefone/e-mail do website validado;
- `cnpj`: procura CNPJ no website e, quando necessário, em páginas públicas descobertas; só aceita o CNPJ após validação cadastral e correspondência de nome/localidade;
- `social`: descobre Instagram/Facebook/LinkedIn a partir do website oficial, sem fazer login ou scraping direto das plataformas.

Cada tarefa persiste `status`, `attempts`, `maxAttempts`, `lastError`, `message`, `lastRunAt` e `completedAt`.

## Estados

`pending → running → retrying → completed | attention | failed | skipped`

Erros transitórios usam retry limitado. `attention` significa que a etapa foi executada corretamente, mas o dado não foi encontrado com confiança suficiente.

## Reprocessamento isolado

A API local expõe:

`POST /api/prospecting-agent/jobs/:jobId/candidates/:candidateId/enrichment/:task/retry`

O retry zera apenas a tarefa selecionada e invalida o snapshot de website necessário à nova tentativa. As demais tarefas mantêm seus contadores e resultados.

## Persistência e resolução

O estado do Agent evolui para schema 3. Cada candidato recebe `candidateId` estável e entra em `job.results` antes do pipeline de enriquecimento, permitindo persistir progresso intermediário. Após o enriquecimento, o Company Resolver roda novamente para aproveitar CNPJ e novas evidências sem enfraquecer a proteção de filiais introduzida no H3.

## Segurança

- somente páginas públicas;
- `robots.txt` respeitado;
- sem CAPTCHA, login ou bypass;
- redes sociais são descobertas por links no site oficial;
- CNPJ descoberto precisa de validação cadastral e correspondência com a empresa candidata.
