# V101.8.1 — RealTalent Connect Setup & Reliability

## Objetivo

Remover a ambiguidade entre “Connect não configurado” e “bridge ativo aguardando celular”, corrigir a comunicação cross-origin entre o CRM e as APIs do Phone Companion e oferecer diagnóstico suficiente para configurar o Connect sem editar código.

## Estados do setup

1. **Bridge offline** — `localhost:3001` não respondeu.
2. **Bridge ativo** — serviço local e API de pareamento respondem; ainda não há telefone online.
3. **Phone online** — companion pareado e presença recente/WebSocket ativo.
4. **Discador pronto** — RealTalent Phone selecionado como dispositivo padrão.
5. **Teste concluível** — CRM pode enviar uma solicitação de chamada ao aparelho.

## CORS

As rotas do Phone API agora recebem os mesmos cabeçalhos CORS seguros usados pela Voice API quando a origem é `http://127.0.0.1:<porta CRM>` ou `http://localhost:<porta CRM>`. Origens não autorizadas não recebem `Access-Control-Allow-Origin` e os endpoints de administração local continuam protegidos pelo origin guard.

## Rede LAN

A detecção usa apenas IPv4 privado e ignora interfaces virtuais. Wi‑Fi é priorizado, depois Ethernet. O setup permite escolher uma das interfaces detectadas e o QR é regenerado apontando para esse IP.

Para forçar um IP específico no launcher/ambiente:

```bash
REALTALENT_CONNECT_LAN_HOST=192.168.1.25 ./start-linux.sh
```

## Diagnóstico

`GET /api/phone/v1/diagnostics` retorna o estado do bridge, pairing, realtime, interfaces LAN, quantidade de celulares e prontidão do discador. A UI apresenta esses itens sem expor detalhes desnecessários de provider.

## Chamada de teste

Depois de um RealTalent Phone ficar online, o setup seleciona automaticamente o aparelho quando ele é o único disponível. O usuário informa um número e envia uma chamada de teste. O celular recebe o contexto “Chamada de teste / RealTalent Connect” e abre o fluxo normal de discador nativo.
