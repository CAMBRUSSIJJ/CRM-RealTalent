# V101.9.0 — Core Metadata Foundation

## Objetivo

Criar uma camada declarativa entre os modelos legados do CRM e a futura arquitetura universal, sem redesenhar a UX nem exigir migração imediata das páginas existentes.

## Registries

### ObjectRegistry

Objetos registrados nesta etapa:

- `lead` → `Lead` (adapter legado comercial);
- `contact` → `ContactRecord` (pessoa);
- `company` → `CompanyRecord`;
- `opportunity` → `OpportunityRecord`.

Cada objeto declara collection de origem, campo de ID, workspace, label principal e adapter.

### FieldRegistry

Registra 44 campos essenciais, incluindo identidade, contexto comercial e campos relacionais. A metadata não substitui ainda `domain/types.ts`; ela descreve o contrato existente.

### RelationRegistry

Relações iniciais:

- Lead → Company;
- Company → Leads;
- Lead → Primary Contact;
- Lead → Opportunity;
- Contact → Company;
- Contact → Leads;
- Opportunity → Lead;
- Opportunity → Company;
- Opportunity → Primary Contact.

## Adapter Layer

`src/platform/records/core-adapters.ts` converte cada modelo para `PlatformRecord` e preserva uma referência `legacy` para retorno sem perda. Nesta versão a UI continua recebendo o shape legado.

Fluxo atual:

```text
Repository
   ↓
WorkspaceSnapshot
   ↓
Snapshot Safety
   ↓
Core Metadata Adapter / Validator
   ↓
WorkspaceSnapshot (mesmo shape)
   ↓
UI atual
```

## Validação

O validator detecta sem mutar dados:

- ID vazio/inválido;
- ID duplicado no mesmo objeto;
- registro em workspace incorreto;
- relação órfã;
- relação cruzando workspace;
- cardinalidade inválida.

Nesta etapa, inconsistências relacionais são diagnóstico. Não há reparo automático destrutivo.

## Inspector interno

Com o CRM aberto, o inspector pode ser consultado pelo console do navegador:

```js
window.__REALTALENT_METADATA__.inspect()
```

Retorna:

- objetos registrados;
- campos registrados;
- relações registradas;
- último diagnóstico do `WorkspaceSnapshot` renderizado.

Não existe botão novo nem mudança de UX para o usuário final.

## Migrations

A V101.9.0 deliberadamente **não adiciona migration SQL**. A fundação é compatível com as tabelas atuais; as 46 migrations existentes continuam checksum-locked. Persistência de metadata customizável ficará para uma etapa posterior, depois do contrato do core estar estabilizado.

## Compatibilidade

- Contatos continuam usando Lead/ContactRecord;
- Pipeline continua usando Lead/OpportunityRecord;
- Account 360 continua usando Company/Contact relationships;
- Comunicação, Connect, WhatsApp e demais módulos não foram redesenhados;
- H15 permanece incorporada;
- Backup schema permanece `100.54`.

## Critério de saída

A release é considerada concluída quando:

1. registries existem e são somente leitura em runtime;
2. adapters preservam IDs e modelos legados;
3. snapshot usado pela UI passa pela camada metadata;
4. dados demo não geram erros/warnings metadata;
5. relação órfã é detectada sem mutação;
6. migrations históricas permanecem íntegras;
7. gates históricos chegam ao `typecheck` sem falso negativo de versão;
8. UI principal permanece sem alteração visual.
