# V101.9.1 — Universal View Engine

## Arquitetura

```text
Legacy UI (Contatos / Pipeline)
        ↓
Legacy Saved View APIs
        ↓
Legacy View Adapters
        ↓
ViewDefinition 101.9.1
  ├─ display
  ├─ columns
  ├─ sort
  ├─ grouping
  ├─ visibility
  └─ Filter AST
        ↓
Universal View Engine
        ↓
Filter / Sort / Group execution
```

A camada é aditiva. Nenhuma tela precisa abandonar seu shape legado nesta versão.

## Filter AST

O filtro não é mais conceitualmente um mapa plano. O modelo universal suporta:

```text
AND / OR / NOT
```

Exemplo:

```text
AND
├─ status = active
├─ OR
│  ├─ temperature = hot
│  └─ priority = urgent
└─ NOT
   └─ doNotContact = true
```

Os operadores válidos dependem do `FieldKind` registrado no `FieldRegistry`. Campos derivados de uma view podem declarar seu próprio tipo para validação.

## Persistência

`ViewDefinition` é persistida em paralelo com as views legadas usando a chave V101.9.1 por workspace. Cada view possui `visibility` (`personal` ou `workspace`) e `ownerId`. A identidade interna é o par `surface + id`, de forma que IDs legados iguais em módulos diferentes não sobrescrevem outra view.

Nesta release, a persistência universal é uma projeção de compatibilidade. A fonte legada continua sendo respeitada por Contatos e Pipeline. A projeção é reconciliada por superfície para remover entradas órfãs sem tocar nas views de outros módulos. Isso evita migration SQL prematura e permite rollback simples.

## Migração de Contatos

`ContactSavedView` é convertido para `ViewDefinition` automaticamente em load/save/reorder/delete. Os starter views, colunas, densidade, cor, ícone e filtros legados permanecem preservados em `extensions` quando não pertencem ao núcleo universal.

## Migração de Pipeline

`PipelineSavedView` é convertido para `ViewDefinition` em load/save. Kanban vira `kanban`; lista, previsão, calendário e funil continuam representados sem perder o modo legado. Deal Health e probabilidades são declarados como campos derivados tipados.

## Inspector

```javascript
window.__REALTALENT_VIEWS__.inspect(workspaceId, ownerId)
```

Retorna views, superfícies registradas e operadores suportados.

## Critério de segurança

- sem alteração visual principal;
- sem migration SQL V101.9.1;
- `WorkspaceSnapshot` e Core Metadata V101.9.0 continuam intactos;
- Supabase de saved views de Contatos não recebe colunas novas;
- PipelinePreferences continua legível por releases anteriores.
