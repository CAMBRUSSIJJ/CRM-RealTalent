# V101.9.2 — Universal Record Page

## Objetivo

Separar o **layout de página de registro** das regras comerciais de cada módulo. A UI de Contato/Pessoa continua visualmente compatível, mas passa a usar um shell e widgets reutilizáveis.

## Arquitetura

```text
Route / Contact page
      ↓
ContactPersonRecordPageAdapter
      ↓
RecordPageRuntimeModel
      ↓
RecordPageDefinition / RecordPageRegistry
      ↓
RecordPageShell
 ├─ left
 │  ├─ identity
 │  ├─ CommunicationWidget
 │  └─ FieldsWidget
 ├─ main
 │  ├─ tabs
 │  ├─ TimelineWidget
 │  ├─ QuickActionsWidget
 │  ├─ notes
 │  └─ Account 360 custom widget
 └─ right
    ├─ RelatedRecordsWidget / Company
    ├─ RelatedRecordsWidget / Opportunities
    └─ Account Health custom widget
```

## Princípio

O universal é o **container** e as capacidades comuns. Regras que diferenciam o RealTalent permanecem específicas: Deal Intelligence, Account 360, política de contato, sessão de ligação, estratégia comercial e comunicação oficial.

## Transição Lead → Pessoa

A definição `contact-person-record-v10192` declara `contact` como objeto canônico desejado e aceita `lead` durante a transição. O adapter procura `primaryContactId` ou um `ContactRecord` primário ligado ao Lead. Se ainda não existir Pessoa canônica, a página continua operacional sobre o Lead e emite apenas um diagnóstico interno `legacy_lead_source`.

A migração definitiva de identidade pertence à V101.9.3.
