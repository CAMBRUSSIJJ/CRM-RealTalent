# V101.9.4 — Global Event Bus

## Objetivo

Eliminar o padrão em que cada ação ou tela decide isoladamente quais dados precisam ser recarregados. A V101.9.4 introduz uma camada de eventos de domínio que desacopla a causa da mudança da forma como Pipeline, Follow-ups, Meu Dia, Comunicação, Notificações e Métricas reagem.

## Componentes

### `domain-event.ts`

Envelope universal com `id`, `name`, `workspaceId`, `occurredAt`, `source`, entidade, correlação, revisão e `payload`.

### `event-bus.ts`

Barramento em memória do browser. Suporta listeners por evento/prefixo, deduplicação, histórico de inspeção, revisões por projeção e `BroadcastChannel` para propagar eventos entre abas do mesmo navegador.

### `event-projections.ts`

Traduz eventos para dois resultados:

1. slices do `WorkspaceSnapshot` que ficaram inválidos;
2. projeções operacionais que precisam reagir.

Exemplo:

```text
pipeline.opportunity.moved
→ commercial + activities + events + automationRuns
→ pipeline + followups + my-day + communications + notifications + metrics
```

### `event-refresh-coordinator.ts`

Recebe eventos e executa refresh seletivo. Eventos locais são drenados imediatamente para que a ação retorne com a UI sincronizada. Eventos externos/realtime são coalescidos com debounce para evitar rajadas de leituras repetidas.

### `realtime-event-bridge.ts`

Converte mudanças de tabelas do Supabase em `realtime.table.changed` e associa cada tabela ao slice/projeções corretos.

### `realtime-status.ts`

Estado compartilhado dos transportes `supabase-realtime` e `communications-sse`. A Central de Comunicação não precisa mais abrir e acompanhar um SSE próprio.

## Fontes de eventos

- ações da UI/repository;
- automações;
- Supabase Realtime;
- Communications Gateway SSE;
- `BroadcastChannel` entre abas;
- eventos de sistema.

## Estratégia de compatibilidade

A V101.9.4 não substitui o `WorkspaceSnapshot`. O Event Bus invalida slices, `loadSnapshotPatch()` lê apenas os domínios necessários e `normalizeSnapshotForRender()` continua executando Canonical Model + Metadata antes do render.

Isso mantém a cadeia:

```text
Repository
→ Canonical Commercial Model
→ Core Metadata Foundation
→ Universal View Engine
→ Universal Record Page
→ UI
```

O Event Bus fica transversal a essa cadeia e coordena quando cada projeção deve ser reconstruída.

## Inspector

```javascript
window.__REALTALENT_EVENTS__.inspect()
```

Retorna:

- total publicado;
- total entregue aos subscribers;
- eventos deduplicados;
- quantidade de subscribers;
- revisões por projeção;
- últimos 100 eventos;
- estado de Supabase Realtime e Communications SSE.

Para limpar somente o histórico do inspector:

```javascript
window.__REALTALENT_EVENTS__.clear()
```

## Banco de dados

Nenhuma migration nova foi adicionada. O barramento é uma infraestrutura de runtime; persistência de execuções fica para o Workflow Runtime 3.0.

A coordenação de invalidação é executada pelo `EventRefreshCoordinator`.
