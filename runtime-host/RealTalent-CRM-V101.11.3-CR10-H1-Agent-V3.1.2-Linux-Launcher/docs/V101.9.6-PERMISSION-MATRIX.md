# V101.9.6 — Permission Matrix

A V101.9.6 substitui verificações dispersas de `role === ...` por uma camada única de autorização em `src/platform/permissions`.

## Modelo

Uma decisão recebe `subject + request`:

- subject: workspace, usuário e papel (`owner/admin/member/viewer`);
- request: recurso, ação, campo opcional e escopo de integração opcional.

A avaliação usa regras priorizadas e termina em **implicit deny** quando nenhuma regra concede a operação.

## Dimensões

- Objeto/recurso: Pessoa, Empresa, Oportunidade, Lead legado, Atividade, Ligação, Agenda, Playbook, Produto, Proposta, Receita, Meta, Automação, Integração, Workspace, Configurações e Auditoria.
- Ação: ler, criar, editar, excluir, exportar, administrar, executar, compartilhar e configurar.
- Campo: `id`, `workspaceId`, `createdAt` e `updatedAt` são protegidos contra escrita pela UI para todos os papéis.
- Integração: scopes como Gmail/Outlook/Calendar/WhatsApp são convertidos em permissões internas, além das regras `accessMode`, `allowedUserIds` e `allowedRoles` da conta conectada.

## Compatibilidade

A política padrão preserva a UX atual:

- owner: controle total, exceto escrita manual em campos estruturais;
- admin: administração e operação completas;
- member: operação comercial; sem gestão de workspace/auditoria/administração de integrações;
- viewer: leitura sem mutações.

## Inspector

```js
window.__REALTALENT_PERMISSIONS__.inspect('member')
```

Retorna a matriz efetiva por recurso e os scopes de integração disponíveis para o papel informado.

## Próximo passo

Overrides por território/registro ficam para uma fase posterior, conforme roadmap. Esta release centraliza objeto/campo/ação/scopes sem introduzir uma migration SQL nova.
