# V101.9.8 — Design System Consolidation

## Objetivo

Reduzir divergência visual causada pela evolução incremental do CRM sem provocar um redesenho disruptivo. Meu Dia e Contatos são a baseline visual.

## Arquitetura

```text
Design Tokens
  ↓
Design System Registry
  ↓
Canonical Primitives
  ├─ Button / IconButton
  ├─ Input / Select / Textarea
  ├─ Tabs
  ├─ Drawer / Dialog
  ├─ DataGrid
  ├─ Surface
  └─ EmptyState
  ↓
Legacy Bridge
  ↓
Módulos existentes
```

## Tokens

A fonte canônica cobre cores, espaçamento, tipografia, alturas de controle, radius, sombras, foco e motion. A identidade RealTalent preserva:

- verde profundo `#04342C`;
- verde de ação `#1D9E75`;
- canvas bege `#F1EFE8`;
- texto principal `#2C2C2A`.

Aliases históricos como `--navy`, `--blue`, `--border`, `--surface`, `--text` e `--muted` agora apontam para esses tokens canônicos na camada final.

## Migração incremental

1. Primitive canônica é criada.
2. Classe histórica equivalente é bridged na stylesheet final.
3. Componentes compartilhados são migrados primeiro.
4. Módulos são migrados por superfície, mantendo o contrato funcional.
5. CSS histórico só é removido quando não possuir consumidores e houver QA visual/runtime.

## Redução de CSS redundante

A folha `design-system-v101.css` não é mais importada no runtime. Ela foi integralmente absorvida pela camada V101.9.8. O arquivo permanece no repositório para preservar auditoria/histórico, mas deixa de disputar cascade. Camadas maiores e específicas permanecem até migração por módulo.

## Primeira onda migrada

- Button compartilhado;
- Modal/Dialog;
- EmptyState;
- busca global;
- tabela principal de Contatos.

## Inspector

`window.__REALTALENT_DESIGN_SYSTEM__.inspect()` expõe versão, tokens, primitives, substituições históricas e estratégia de migração.

## Não objetivos desta versão

- redesign de Meu Dia;
- redesign de Contatos;
- dark mode novo;
- remoção em massa de CSS histórico;
- mudança do modelo de dados;
- migration SQL.
